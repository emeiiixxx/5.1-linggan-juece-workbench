# 任务退出、并行与恢复规则

版本：1.0  
状态：除“异常重试扣费”外，其余规则已确认  
适用范围：商品企划、客户提案、服装设计、图案设计及企划案任务

## 1. 已确认产品规则

| 场景 | 规则 |
| --- | --- |
| 返回首页 | 仅离开任务页面，不清空、不暂停、不取消任务。任务继续执行，用户可重新进入查看进度。 |
| 切换任务 | 原任务继续执行，新任务进入前台；切换行为不改变任务状态。 |
| 并行上限 | 最多同时存在 5 个未完成任务。第 6 个任务不得创建。 |
| 上限提示 | `当前任务数量已达上限，请稍后再试。` 被拦截的输入和附件不得清空。 |
| 暂停 | 用户点击暂停后，停止当前运行步骤，保留已成功节点和已有产物。 |
| 继续 | 暂停任务可以继续，从暂停前最近一个成功节点恢复，不覆盖已有结果。 |
| 购买积分 | 购买成功后，从最后一个已成功提交或确认的节点继续，不重复执行成功步骤。 |
| 刷新页面 | 保留任务记录、状态、当前任务和已有产物；重新连接任务服务后根据服务端 checkpoint 恢复。 |
| 只读案例 | 只能查看，不提供输入框、完成建议、编辑、继续生成或复制为新任务入口。 |

## 2. 哪些状态占用 5 个并行名额

占名额：

- 排队中
- 分析中 / 生成中
- 等待用户确认
- 暂停中
- 网络异常、解析失败、积分不足等待恢复

不占名额：

- 已完成
- 已取消
- 已删除

返回首页、切换任务、关闭浏览器或刷新页面都不释放名额。

## 3. 恢复节点的定义

“上一步”统一定义为：最后一个已经由服务端确认成功，并写入 checkpoint 的业务节点。不能按用户看见的上一张页面、上一条消息或前端路由理解。

至少需要记录：

- `taskId`
- `status`
- `workflow`
- `checkpoint`
- 用户已确认的输入、表单和选图
- 已生成产物及版本
- 当前运行步骤的幂等键
- 积分预扣、实扣或退款记录
- 最后更新时间

购买积分、网络重连和刷新页面都必须先读取同一份 checkpoint，再决定继续哪个步骤。

## 4. 前端原型与正式产品边界

当前前端原型使用本地存储验证以下行为：

- 刷新后恢复任务列表、任务状态、当前打开任务、项目和业务偏好档案选择。
- 同一页面会话内返回首页或切换任务时，保留已打开任务的组件状态并继续计时。
- 创建任务前检查 5 个未完成任务上限。

本地存储不是正式任务恢复方案。正式产品必须由任务服务保存 checkpoint；浏览器本地数据只能作为展示缓存，不能作为扣费、产物或任务状态真源。

## 5. 待产品确认

### 异常重试是否重复扣积分

在产品给出结论前：

- 前端不得自行显示“会扣费”或“不会扣费”的承诺。
- 开发不得在重试按钮点击时直接再次扣费。
- 技术方案必须预留幂等键，防止同一运行步骤因刷新、重连或重复点击产生多次扣费。
- 验收报告中保持 `TBD`，不能视为已关闭。

## 6. 验收用例

- [ ] 进行中的任务返回首页后状态不变，重新进入可继续查看。
- [ ] 两个任务同时运行时，切换任务不会把另一个任务改成待完成。
- [ ] 已有 5 个未完成任务时，第 6 个创建被拦截，输入和附件保留。
- [ ] 完成或删除一个任务后，可以再创建一个任务。
- [ ] 暂停运行步骤后可以继续，已有结果不被覆盖。
- [ ] 积分购买成功后从最后成功 checkpoint 继续。
- [ ] 刷新后恢复到同一任务；服务端状态优先于本地缓存。
- [ ] 只读案例没有输入、建议或复制入口。
