# 任务退出、并行与恢复规则

版本：1.2

状态：规则已确认

适用范围：商品企划、客户提案、服装设计、图案设计及企划案任务

## 1. 已确认产品规则

| 场景 | 规则 |
| --- | --- |
| 返回首页 | 仅离开任务页面，不清空、不暂停、不取消任务。任务继续执行，用户可重新进入查看进度。 |
| 切换任务 | 原任务继续执行，新任务进入前台；切换行为不改变任务状态。 |
| 任务数量 | 暂不设上限；用户可以持续创建任务，不做数量校验或超限拦截。 |
| 暂停 | 用户点击暂停后，停止当前运行步骤，保留已成功节点和已有产物。 |
| 继续 | 暂停任务可以继续，从暂停前最近一个成功节点恢复，不覆盖已有结果。 |
| 购买积分 | 购买成功后，从最后一个已成功提交或确认的节点继续，不重复执行成功步骤。 |
| 异常扣费与返还 | 任务开始时先扣除积分；若系统确认本次失败属于异常，自动返还对应积分。返还过程无需用户申请或执行其他操作。 |
| 刷新页面 | 保留任务记录、状态、当前任务和已有产物；重新连接任务服务后根据服务端 checkpoint 恢复。 |
| 只读案例 | 案例内容仍不可编辑、继续生成或直接创建任务；任务流右下提供“复制初始输入到新建任务”，点击后返回首页，将案例第一句用户输入回填到对应任务分类的输入框，等待用户确认并发送。 |

## 2. 恢复节点的定义

“上一步”统一定义为：最后一个已经由服务端确认成功，并写入 checkpoint 的业务节点。不能按用户看见的上一张页面、上一条消息或前端路由理解。

至少需要记录：

- `taskId`
- `status`
- `workflow`
- `checkpoint`
- 用户已确认的输入、表单和选图
- 已生成产物及版本
- 当前运行步骤的幂等键
- 积分扣除、异常返还和幂等流水记录
- 最后更新时间

购买积分、网络重连和刷新页面都必须先读取同一份 checkpoint，再决定继续哪个步骤。

## 3. 前端原型与正式产品边界

当前前端原型使用本地存储验证以下行为：

- 刷新后恢复任务列表、任务状态、当前打开任务、项目和业务偏好档案选择。
- 同一页面会话内返回首页或切换任务时，保留已打开任务的组件状态并继续计时。
- 用户可以连续创建任务；前端不统计未完成任务数量，也不显示任务超限提示。

本地存储不是正式任务恢复方案。正式产品必须由任务服务保存 checkpoint；浏览器本地数据只能作为展示缓存，不能作为扣费、产物或任务状态真源。

## 4. 异常扣费与自动返还

- 任务开始时先扣除积分。
- 若系统确认本次失败属于异常，账务系统自动返还对应积分。
- 返还为无感操作，用户无需提交申请、点击退款或执行其他操作。
- 同一运行步骤必须使用幂等键，避免重复扣除或重复返还积分。
- 前端不提供手动返还入口，积分余额以账务系统记录为准。


## 5. 验收用例

- [ ] 进行中的任务返回首页后状态不变，重新进入可继续查看。
- [ ] 两个任务同时运行时，切换任务不会把另一个任务改成待完成。
- [ ] 连续创建任务时不做数量校验，不显示任务超限提示。
- [ ] 暂停运行步骤后可以继续，已有结果不被覆盖。
- [ ] 积分购买成功后从最后成功 checkpoint 继续。
- [ ] 任务开始时扣除积分；确认属于系统异常后自动返还，且不会重复扣除或重复返还。
- [ ] 刷新后恢复到同一任务；服务端状态优先于本地缓存。
- [ ] 只读案例没有编辑、完成建议或继续生成入口；任务流右下“复制初始输入到新建任务”只回填草稿，不自动发送。
- [ ] 复制案例初始输入后，首页切换到案例对应任务分类；企划案进入企划案编辑器，其他类型进入各自输入框。
